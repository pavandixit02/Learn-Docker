🐳 Docker Images & Containers

Complete beginner-friendly guide to Docker Images, Docker Containers, their lifecycle, commands, relationship, and differences.

1. What is a Docker Image?

A Docker Image is a read-only template or package that contains everything required to create and run a container.

An image can contain application code, libraries, dependencies, configuration files, environment information, and instructions about how the application should start.

Simple Definition:

Docker Image = A blueprint/template used to create Docker Containers.

Why do we need Docker Images?

Suppose you have a Python application. To run it successfully, you may need Python, external libraries, application code, configuration, and other dependencies.

Instead of installing all these things manually on every machine, we can package the required environment into a Docker Image.

Example

Suppose your application requires:

  • Ubuntu Linux
  • Python 3.12
  • Flask
  • Requests
  • Application source code
  • Required configuration

These requirements can be defined while building an image.

Docker Image is Read-Only

A Docker Image itself is immutable/read-only. When a container is started from an image, Docker adds a writable container layer on top of the image.

Therefore, multiple containers can be created from the same image while each container has its own writable layer.

2. Docker Image Structure

Docker images are built using multiple layers. Each instruction in a Dockerfile can create a filesystem layer as part of the image build process.

Base Image
→
Dependencies
→
Application
→
Docker Image

Example Dockerfile

FROM python:3.12

WORKDIR /app

COPY requirements.txt .

RUN pip install -r requirements.txt

COPY . .

CMD ["python", "app.py"]

What does each instruction do?

Instruction Purpose
FROM Defines the base image.
WORKDIR Sets the working directory inside the image.
COPY Copies files from the build context into the image.
RUN Executes commands while building the image.
CMD Provides the default command when a container starts.

3. Important Docker Image Commands

List Images

docker images

Pull an Image

docker pull nginx

This downloads the Nginx image from a container registry, such as Docker Hub.

Build an Image

docker build -t my-app:1.0 .

Remove an Image

docker rmi my-app:1.0

Inspect an Image

docker image inspect nginx

View Image History

docker history nginx

4. What is a Docker Container?

A Docker Container is an isolated runtime environment created from a Docker Image.

Simple Definition:

Container = A running/created instance of a Docker Image.

Image vs Running Application

An image is the packaged application environment. A container is where that packaged application actually runs.

🏠 Real-Life Analogy

Think of a house blueprint.

  • Blueprint = Docker Image
  • Actual House = Docker Container

One blueprint can be used to create multiple houses. Similarly, one Docker image can be used to create multiple containers.

What happens when a container starts?

  1. Docker finds the required image.
  2. Docker creates a container filesystem and runtime configuration.
  3. Docker adds a writable layer over the image layers.
  4. Docker configures networking and other requested resources.
  5. Docker starts the process specified by the image/container configuration.

docker create --name web nginx

The -d option runs the container in detached mode.

Restart a Container

docker restart web

Remove a Container

docker rm web

List Running Containers

List All Containers

docker ps -a

6. Relationship Between Image and Container

The relationship between Docker Images and Containers is one of the most important concepts to understand in Docker.

Dockerfile
→
Image
→
Container
→
Application

One Image → Multiple Containers

The same image can be used to create multiple containers. 

docker run -d --name web1 nginx
docker run -d --name web2 nginx
docker run -d --name web3 nginx

In this example, all three containers are created from the same Nginx image.

Important Concept:

Image is the template. Container is the runtime instance.

7. Difference Between Docker Image and Container

Docker Image Docker Container
Image is a template/package. Container is a runtime instance created from an image.
Images are immutable/read-only. Container has a writable layer on top of the image.
Image is used to create containers. Container runs the application.
Images are stored locally or in registries. Containers exist on a Docker host while they are created.
An image can have multiple versions/tags. Containers have their own names and IDs.
Example: nginx:latest Example: my-nginx-container
Created using Dockerfile/build process. Created using docker run/create commands.
Does not normally represent a running process by itself. Runs a process/application.

8. Image vs Container — Easy Way to Remember

Think of an image as a blueprint.

It tells Docker what should be inside the container.

🏠 Container

Think of a container as the actual house created from the blueprint.

This is where the application runs.

🏭 Dockerfile

Think of Dockerfile as the instructions used to create the blueprint.

9. Complete Practical Example

Let's create an Nginx container from the Nginx image.

Step 1: Download Image

docker pull nginx

Step 2: Check Image

docker images

Step 3: Create and Start Container

docker run -d --name my-nginx -p 8080:80 nginx

Step 4: Check Container

docker ps

Step 5: View Logs

docker logs my-nginx

Step 6: Stop Container

docker stop my-nginx

Step 7: Remove Container

docker rm my-nginx
Remember:

Removing a container does not automatically mean the image is removed. Images and containers are separate Docker objects.
