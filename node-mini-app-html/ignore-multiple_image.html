2. What is .dockerignore?

.dockerignore ek special Docker file hai jisme hum un files aur directories ko define karte hain jinhe Docker image build ke context me include nahi karna chahiye.

Simple Definition:

.dockerignore Docker ko batata hai: "In files ko Docker build context me mat bhejo."

Why do we need .dockerignore?

Jab hum command run karte hain: 

docker build -t node-docker-app:1.0 .

Last ka . current directory ko build context banata hai.

Docker build ke liye context me unnecessary files bhi ho sakti hain. `.dockerignore` un files ko exclude karne me help karta hai.

🚫 Unnecessary Files

Files jo image ke liye required nahi hain, unhe exclude kar sakte hain.

⚡ Smaller Context

Build context ko unnecessary files se free rakhne me help karta hai.

🔐 Sensitive Files

Local secrets aur configuration files ko build context se exclude karne me help karta hai.

🧹 Cleaner Builds

Sirf required project files ko image build process me include karna easier hota hai.

Har Entry Ka Meaning

Entry Purpose
node_modules Local machine ke installed Node.js dependencies ko build context se exclude karta hai.
npm-debug.log npm ke debug logs ko exclude karta hai.
.git Git repository metadata ko build context se exclude karta hai.
.gitignore Git configuration file ko exclude karta hai.
.env Local environment variables file ko exclude karta hai.
.env.* Environment-specific .env files ko exclude karne ke liye pattern.
Dockerfile Dockerfile ko build context se exclude karna possible hai, lekin Dockerfile khud build instruction ke roop me separately read karta hai. Isliye ise ignore karna optional hai.
README.md Documentation ko image me copy hone se rokta hai.
.vscode VS Code local settings ko exclude karta hai.
coverage Testing coverage output ko exclude karta hai.
Important:

`.dockerignore` security ka complete replacement nahi hai. Sensitive data ko image me include na karna important hai, aur secrets ko Dockerfile me hard-code nahi karna chahiye.

8. Docker Image Versioning Kya Hai?

Docker images ko versions/tags dena image management ka important part hai.

Example: 
node-docker-app:1.0
node-docker-app:1.1
node-docker-app:2.0

Yahan:

  • node-docker-app = image name
  • 1.0 = image tag/version
  • 1.1 = updated version
  • 2.0 = major version

9. Docker Image Tags Kya Hote Hain?

Tag image ke different versions ya variants ko identify karne ke liye use hota hai.

Image Name Format

IMAGE_NAME:TAG

Example

node-docker-app:1.0
Part Meaning
node-docker-app Docker image ka naam.
: Image name aur tag ko separate karta hai.
1.0 Image ka tag/version.

15. Version Management Strategy

Docker image versions ke liye commonly structured tags use kiye ja sakte hain.

Version Example Meaning
Patch 1.0.1 Small bug fixes or backward-compatible changes.
Minor 1.1.0 New backward-compatible features.
Major 2.0.0 Major changes that may not remain backward compatible.
Important:

Docker tags themselves are just labels. Docker does not automatically enforce Semantic Versioning rules. Your team should define and follow its own tagging policy.

16. Existing Image Ko New Tag Dena

Agar image already build hai, to docker tag command se usi image ko ek additional tag diya ja sakta hai.

Example

docker tag node-docker-app:1.0 node-docker-app:stable

Ab same image ko: 

node-docker-app:1.0
node-docker-app:stable

dono tags se reference kiya ja sakta hai.

Important:

Tagging normally image ko duplicate karke poori nayi copy nahi banata; tag image ko reference karta hai.

20. Image Version vs Container Version

Image Container
node-docker-app:1.0 node-app-v1
Application ka packaged version. Us image ka running instance.
Multiple containers create kar sakti hai. Ek specific runtime instance hai.
Tag se version identify kar sakte hain. Name/ID se specific container identify hota hai.

21. Common Mistakes

❌ Mistake 1 — .dockerignore ko Dockerfile samajhna

Dono files ka purpose different hai.

Dockerfile → Image build instructions

.dockerignore → Build context se files exclude karna

❌ Mistake 2 — Har Version Ka Same Container Name

Ek hi host par same naam ke multiple containers nahi banaye ja sakte.

Use: 

node-app-v1
node-app-v11
node-app-v2

❌ Mistake 3 — Same Host Port Use Karna

Agar do containers ko same host port par bind karoge, port conflict ho sakta hai.

Example: 

Version 1.0 → 3000:3000
Version 1.1 → 3001:3000
Version 2.0 → 3002:3000

❌ Mistake 4 — Secrets Image Me Copy Karna

Passwords, API keys aur secrets ko Dockerfile ya image ke andar hard-code nahi karna chahiye.
