1. Docker Compose Kya Hai?

Docker Compose ek tool hai jiske through hum multiple containers, services, networks aur volumes ko ek YAML configuration file me define karke manage kar sakte hain.

Simple words me:

Docker Compose = Docker application ka configuration ek file me define karke build, create, start aur manage karne ka convenient way.

Normal Docker commands me hume baar-baar long commands likhni pad sakti hain. Compose me hum configuration ko compose.yaml me define kar dete hain.

Without Compose

docker build -t node-docker-app:1.0 .

docker volume create node-app-data

docker run -d \
  --name node-app-volume \
  -p 3000:3000 \
  -v node-app-data:/app/data \
  node-docker-app:1.0

With Compose

docker compose up -d
Compose ka major advantage ye hai ki application ki configuration repeatable aur easily manageable ho jati hai.

2. compose.yaml File Kya Hoti Hai?

compose.yaml ek YAML configuration file hoti hai jisme hum Docker application ke required services aur unki configuration define karte hain.

Is file ka naam commonly: 

compose.yaml

ho sakta hai.

Traditional projects me docker-compose.yml bhi bahut common naam hai. Modern Docker Compose workflows me compose.yaml preferred filename ke roop me use kiya ja sakta hai.

3. YAML Kya Hai?

YAML ka full form commonly YAML Ain't Markup Language diya jata hai.

YAML ek human-readable configuration/data format hai. Docker Compose YAML syntax ka use karta hai.

Basic YAML Example

name: my-app
version: 1.0

YAML me indentation important hoti hai.

Important: YAML me indentation ke liye tabs avoid karo. Spaces ka consistent use karo.

4. Basic compose.yaml Structure

services:

  app:

    build:
      context: .

    ports:
      - "3000:3000"

Is small example me hum ek service define kar rahe hain.

5. compose.yaml Ke Important Keywords

Keyword Purpose
services Application ke containers/services define karta hai.
build Local Dockerfile se image build karne ke liye.
context Build context specify karta hai.
dockerfile Kaunsa Dockerfile use karna hai, ye specify kar sakta hai.
image Use/build/run hone wali image ka naam/tag specify karta hai.
container_name Container ka custom name specify karta hai.
ports Host aur container ports map karta hai.
volumes Persistent storage ya mounts define karta hai.
environment Environment variables define karta hai.
command Container start hone par command override/run kar sakta hai.
restart Container restart policy define karta hai.
depends_on Services ke startup dependency relationship ko define karta hai.
networks Services ke network configuration ko define karta hai.

6. services Keyword

services Compose file ka sabse important section hai.

Iske andar hum application ke individual services define karte hain. 

services:

  app:

    image: node-docker-app:1.0

Yahan app service ka naam hai.

Service name ko aap apne project ke according choose kar sakte ho, jaise app, web, backend, database etc.

7. build Keyword

build ka use Dockerfile ke through image build karne ke liye hota hai. 

services:

  app:

    build:
      context: .

Iska meaning: 

Current directory
      ↓
Build Context
      ↓
Dockerfile
      ↓
Docker Image

8. context Keyword

context Docker build context specify karta hai. 

build:
  context: .

. ka meaning current directory hai.

Agar compose.yaml project root me hai aur Dockerfile bhi current directory me hai, to: 

context: .

common configuration hai.

9. dockerfile Keyword

Agar Dockerfile ka naam/location default se different ho, to dockerfile specify kar sakte hain. 

services:

  app:

    build:
      context: .
      dockerfile: dockerfile

Hamare project me Dockerfile ka naam lowercase dockerfile hai, isliye ye explicitly specify karna useful hai.

10. image Keyword

image ke through hum Docker image ka naam aur tag define kar sakte hain. 

services:

  app:

    image: node-docker-app:1.0

Iska meaning: 

Repository / Image Name
        :
       Tag

node-docker-app:1.0
Difference:
build = image banane ka process.
image = image ka naam/reference.

12. Hamara First compose.yaml

services:

  app:

    build:
      context: .
      dockerfile: dockerfile

    image: node-docker-app:1.0

    container_name: node-app-compose

    ports:
      - "3000:3000"

Is File Ka Meaning

  1. services → application service define karta hai.
  2. app → service ka naam.
  3. build → Docker image build hogi.
  4. context: . → current directory build context hai.
  5. dockerfile: dockerfile → hamara Dockerfile use hoga.
  6. image → generated image ka naam/tag.
  7. container_name → container ka custom name.
  8. ports → port mapping.

13. volumes Keyword

Previous part me humne Docker Volume padha tha. Ab usi volume ko Compose ke through define karenge. 

services:

  app:

    build:
      context: .
      dockerfile: dockerfile

    image: node-docker-app:1.0

    container_name: node-app-compose

    ports:
      - "3000:3000"

    volumes:
      - node-app-data:/app/data

volumes:

  node-app-data:

Yahan: 

node-app-data
      ↓
Docker Volume

/app/data
      ↓
Container ke andar mount point
Compose required named volume ko manage karne me help karega.

14. environment Keyword

Application ke environment variables define karne ke liye environment use kiya ja sakta hai. 

services:

  app:

    build:
      context: .
      dockerfile: dockerfile

    environment:
      NODE_ENV: production
      APP_NAME: node-docker-app

Container ke andar application in variables ko access kar sakti hai.

Node.js example: 

console.log(process.env.NODE_ENV);
console.log(process.env.APP_NAME);

15. command Keyword

command container ke default command ko override kar sakta hai. 

services:

  app:

    image: node-docker-app:1.0

    command: node index.js

Agar Dockerfile me already: 

CMD ["node", "index.js"]

hai aur Compose me different command define kiya hai, to Compose wala command use ho sakta hai.

16. restart Keyword

Container ke restart behavior ko control karne ke liye restart use hota hai. 

services:

  app:

    restart: unless-stopped

Common policies:

  • no
  • always
  • on-failure
  • unless-stopped

17. depends_on Keyword

Jab ek application multiple services use karti hai, tab service dependency define karne ke liye depends_on use kiya ja sakta hai.

Example: 

services:

  app:

    depends_on:
      - database

  database:

    image: mongo:latest

Is example me app service ka dependency relationship database ke saath define kiya gaya hai.

Important: depends_on ko service-start ordering ke concept ke roop me samjho. Iska matlab ye automatically guarantee nahi karta ki database application requests accept karne ke liye fully ready hai.

18. networks Keyword

Multiple services ke communication ke liye custom Docker network define kiya ja sakta hai. 

services:

  app:

    image: node-docker-app:1.0

    networks:
      - app-network

networks:

  app-network:

Compose services ko same network par connect kar sakta hai.

19. Complete compose.yaml — Our Mini Project

Ab tak ke important concepts ko combine karke complete Compose file: 

services:

27. Pull Karke Compose Se Run Karna

Complete flow: 

docker compose pull
docker compose up -d

Ya agar image already available nahi hai aur Compose configuration image ko reference karti hai: 

docker compose up -d

Compose required image ko available karne ke liye pull kar sakta hai, depending on the configuration and local image state.

28. Build vs Pull

Build Pull
Local Dockerfile se image create karta hai. Registry/Docker Hub se existing image download karta hai.
Source code available hona chahiye. Registry par image available honi chahiye.
docker compose build docker compose pull

29. Build + Run Ek Saath

Agar local Dockerfile se image build karke service start karni hai: 

docker compose up -d --build

Ye useful hai jab Dockerfile ya application code me changes kiye gaye hain aur latest image build karke container start karna hai.

30. Multiple Containers / Scaling Concept

Compose services ko multiple instances ke concept ke saath run kar sakta hai. 

docker compose up -d --scale app=2
Agar service me fixed container_name diya hua hai, scaling ke saath conflict ho sakta hai. Scaling practice ke liye usually container_name avoid karna better hota hai.

33. Common Errors

Error 1 — Compose file nahi mil rahi

no configuration file provided

Ensure karo ki terminal us directory me hai jahan compose.yaml present hai. 

ls

Error 2 — YAML indentation problem

YAML indentation carefully check karo.

Error 3 — Port already in use

Bind for 0.0.0.0:3000 failed:
port is already allocated

Existing container check: 

docker ps

Ya host port change karo: 

ports:
  - "3001:3000"

Error 4 — Image nahi mil rahi

Docker Hub image ka exact repository name aur tag check karo. 

docker pull pavandixit/node-docker-app:1.0

Error 5 — Docker daemon issue

Agar Docker daemon running nahi hai to Compose commands bhi fail ho sakti hain. 

docker info

35. Docker Compose Interview Questions

Q1. Docker Compose kya hai?

Docker Compose ek tool hai jo YAML configuration ke through multi-container applications ko define aur manage karne me help karta hai.

Q2. compose.yaml kya hoti hai?

Ye YAML configuration file hoti hai jisme services, images, builds, ports, volumes, networks aur other settings define ki ja sakti hain.

Q3. build aur image me kya difference hai?

build local Dockerfile/context se image create karne ke liye hota hai, jabki image image name/tag ko reference karta hai.

Q4. docker compose build kya karta hai?

Compose configuration ke build instructions ke according Docker image build karta hai.

Q5. docker compose up kya karta hai?

Compose application ke defined services ko create/start karta hai aur required resources configure karta hai.

Q6. docker compose pull kya karta hai?

Compose file me referenced registry images ko pull karta hai.

Q7. docker compose down kya karta hai?

Compose application ke containers aur associated resources ko remove/stop karne ke workflow me use hota hai.

Q8. Volume Compose me kaise define karte hain?
