GitLab Server with Docker Compose + Volumes

Continue the previous GitLab Docker Compose setup by adding persistent storage using Bind Mount Volumes.

1. Previous Setup Se Continue

Previous lesson me humne Docker Compose ka use karke GitLab Server ka container create aur run kiya tha.

Lekin ek important problem thi: GitLab ka data container ke andar stored tha.

Agar container remove ho jaye, to container ke andar stored important data lose ho sakta hai.

Is problem ko solve karne ke liye hum Volumes / Persistent Storage use karenge.

2. Problem Without Volume

GitLab Container ↓ /etc/gitlab /var/log/gitlab /var/opt/gitlab ↓ Container ke andar data ↓ Container remove ↓ Data loss ka risk

Docker container ko generally temporary/replaceable unit ki tarah treat kiya jata hai.

Isliye databases, Git repositories, configuration aur logs jaise important data ko container lifecycle se independent rakhna better practice hai.

3. Solution — Volumes

Docker volume ya bind mount ka purpose container ke important data ko container ke bahar store karna hai.

Host Machine ./gitlab/data ./gitlab/logs ./gitlab/config ↓ Docker Mount ↓ GitLab Container /var/opt/gitlab /var/log/gitlab /etc/gitlab
Main Concept: Container delete ho sakta hai, lekin host machine par stored data ko preserve kiya ja sakta hai.

4. Complete Docker Compose File

Ab previous Compose configuration me volumes add karenge. 

services:

  gitlab-server:

    image: 'gitlab/gitlab-ce'

    container_name: my-gitlab-server-volume

    ports:
      - '8000:80'

    environment:
      GITLAB_OMNIBUS_CONFIG: |
        gitlab_rails['initial_root_password'] = 'YOUR_PASSWORD'
        puma['worker_processes'] = 0

    volumes:
      - ./gitlab/data:/var/opt/gitlab
      - ./gitlab/logs:/var/log/gitlab
      - ./gitlab/config:/etc/gitlab
Security: Real password ko Compose file me plain text ke form me Git repository me commit nahi karna chahiye. Learning example me placeholder use karein.

5. version Keyword

version: '5.5.1'

Ye GitLab version nahi hai.

Historically Docker Compose file format/schema version specify karne ke liye version field use hoti thi.

Modern Docker Compose me top-level version field generally obsolete/ignored hai. New Compose files me ise normally omit karna better hai.

Agar GitLab ka specific version select karna ho to image tag use karein: 

image: 'gitlab/gitlab-ce:SPECIFIC_TAG'

6. services Keyword

services:

services ke andar Docker Compose ke containers/services define kiye jate hain. 

services:

  gitlab-server:

Yahan gitlab-server ek service ka naam hai.

7. image Keyword

image: 'gitlab/gitlab-ce'

image batata hai ki container kis Docker image se create hoga.

Yahan GitLab Community Edition image use ho rahi hai.

8. container_name Keyword

container_name: my-gitlab-server-volume

Ye container ko custom readable name deta hai. 

docker ps

Output me container ka naam: 

my-gitlab-server-volume

Is naam ka use karke commands run kar sakte hain: 

docker logs my-gitlab-server-volume

docker exec -it my-gitlab-server-volume bash

9. ports Keyword

ports:
  - '8000:80'

Format: 

HOST_PORT:CONTAINER_PORT

Is case me:

  • 8000 → Host machine port
  • 80 → GitLab container HTTP port

Browser: 

http://localhost:8000

GITLAB_OMNIBUS_CONFIG: |

12. volumes Keyword — Main Topic

volumes:

volumes section ka purpose container ke andar ke important data ko container ke bahar persistent storage ke saath connect karna hai.

Hamare example me teen mounts hain: 

volumes:

  - ./gitlab/data:/var/opt/gitlab

  - ./gitlab/logs:/var/log/gitlab

  - ./gitlab/config:/etc/gitlab
Ye teen different host directories ko GitLab container ke different directories ke saath map kar rahe hain.

13. Volume Syntax Samjho

- HOST_PATH:CONTAINER_PATH

Isko yaad rakhne ka easiest method:

HOST : CONTAINER

Example: 

- ./gitlab/data:/var/opt/gitlab

Iska meaning:

./gitlab/data ↓ ↓ /var/opt/gitlab

Host machine ke ./gitlab/data directory ko container ke /var/opt/gitlab directory par mount karo.

14. ./ ka Kya Meaning Hai?

./gitlab/data

./ ka meaning hai: current directory.

Agar Compose file yahan hai: 

/home/pavan/Desktop/Learn-Docker/
setup-run gitlab-docker/
volume-with-compose_file/
compose.yml

To: 

./gitlab/data

approximately is directory ko refer karega: 

/home/pavan/Desktop/Learn-Docker/
setup-run gitlab-docker/
volume-with-compose_file/
gitlab/data
Important: Relative bind-mount paths normally Compose project/Compose file context ke relative resolve hote hain.

15. First Volume — GitLab Application Data

- ./gitlab/data:/var/opt/gitlab

Ye GitLab ke important application/data directory ko host machine ke directory ke saath map karta hai.

Part Meaning
./gitlab/data Host machine ka directory
: Host aur container ke beech mapping separator
/var/opt/gitlab Container ke andar GitLab application data location

Simple language me:

Host: ./gitlab/data ↕ Container: /var/opt/gitlab

GitLab ka important application data host machine ke ./gitlab/data directory ke through persist kiya ja sakta hai.

16. Second Volume — GitLab Logs

- ./gitlab/logs:/var/log/gitlab

Ye GitLab ke logs ko host machine par persist karne ke liye directory mapping provide karta hai.

Part Meaning
./gitlab/logs Host machine ka logs directory
/var/log/gitlab Container ke andar GitLab logs directory
Host ./gitlab/logs ↓ Container /var/log/gitlab ↓ GitLab Logs

Isse container lifecycle ke bahar bhi logs ko host side par preserve karna easier hota hai.

17. Third Volume — GitLab Configuration

- ./gitlab/config:/etc/gitlab

Ye GitLab configuration directory ko host machine par persist karne ke liye mount karta hai.

Part Meaning
./gitlab/config Host machine ka configuration directory
/etc/gitlab Container ke andar GitLab configuration location
Host ./gitlab/config ↓ Container /etc/gitlab ↓ GitLab Configuration

18. Teen Volumes Ek Saath Samjho

Host Directory Container Directory Purpose
./gitlab/data /var/opt/gitlab GitLab application/data
./gitlab/logs /var/log/gitlab GitLab logs
./gitlab/config /etc/gitlab GitLab configuration

19. Host Machine Par Directory Structure

30. Container Remove/Recreate Concept

Bind mount ka main benefit tab aur clearly samajh aata hai jab container recreate hota hai. 

docker compose down

Phir: 

docker compose up -d

Naya container create hone ke baad bhi host ke mounted directories available rehti hain.

Container #1 ↓ deleted ↓ Host directories remain ./gitlab/data ./gitlab/logs ./gitlab/config ↓ Container #2 ↓ Same mounted data

31. Ye Named Volume Hai Ya Bind Mount?

Hamari configuration: 

- ./gitlab/data:/var/opt/gitlab

Named Docker volume nahi hai.

Ye Bind Mount hai.

Kyunki left side par humne directly host filesystem path diya hai: 

./gitlab/data

Named Volume Example

volumes:
  gitlab-data:

services:
  gitlab-server:
    volumes:
      - gitlab-data:/var/opt/gitlab

Bind Mount Example

services:
  gitlab-server:
    volumes:
      - ./gitlab/data:/var/opt/gitlab

32. Bind Mount vs Named Volume

Feature Bind Mount Named Volume
Host path directly specify? Yes No
Example ./gitlab/data:/var/opt/gitlab gitlab-data:/var/opt/gitlab
Files easily visible on project directory? Yes Not normally in project directory
Developer control High Docker manages volume location

33. Read-Only Volume Option

Docker mounts ko read-only bhi banaya ja sakta hai: 

- ./config:/etc/app:ro

Yahan :ro ka meaning: read-only.

Container mounted data ko read kar sakta hai lekin write nahi kar sakta.

GitLab ke writable data/config/log mounts ke liye blindly :ro use nahi karna chahiye.

34. volumes Keyword Ko Ek Baar Properly Samjho

volumes:
  - ./gitlab/data:/var/opt/gitlab
  - ./gitlab/logs:/var/log/gitlab
  - ./gitlab/config:/etc/gitlab

Yahan volumes service-level configuration hai. Iske andar list items define karte hain ki kaun sa host path container ke kis path ke saath mount hoga.

Formula: 
volumes:
  - HOST_PATH:CONTAINER_PATH

Is formula ko yaad rakhna Docker/DevOps interviews aur practical work dono ke liye important hai.

35. Complete Working Flow

compose.yml ↓ docker compose config ↓ Docker Compose ↓ GitLab Image ↓ GitLab Container ↓ ┌─────────────────────────────┐ │ Volume / Bind Mount │ └─────────────────────────────┘ ↓ ↓ ↓ ./gitlab/data ./gitlab/logs ./gitlab/config ↓ ↓ ↓ /var/opt/gitlab /var/log/gitlab /etc/gitlab ↓ Persistent GitLab Storage ↓ http://localhost:8000

36. Common Mistakes

1. Wrong indentation

volumes:
- ./gitlab/data:/var/opt/gitlab

Better indentation: 

volumes:
  - ./gitlab/data:/var/opt/gitlab

2. Host and container path reverse karna

Correct: 

HOST:CONTAINER

Example: 

./gitlab/data:/var/opt/gitlab

3. Same host port already occupied

ports:
  - '8000:80'

Agar port 8000 already kisi aur container/application ne use kiya hai, to new port use kar sakte hain: 

ports:
  - '8001:80'

4. GitLab startup time ignore karna

GitLab ek lightweight container nahi hai. First startup me time lag sakta hai.

5. Password repository me commit karna

Real credentials ko GitHub/GitLab repository me push nahi karna chahiye.

37. Interview Questions

Q1. Docker volume kya hota hai?

Docker volume/container storage mechanism hai jo container ke lifecycle se data ko independent rakhne me help karta hai.

Q2. Bind mount kya hota hai?

Bind mount host machine ke specific filesystem path ko container ke specific path par mount karta hai.

Q3. ./gitlab/data:/var/opt/gitlab ka meaning?

Host ke ./gitlab/data path ko container ke /var/opt/gitlab path par mount karna.

Q4. HOST:CONTAINER order kya hota hai?

HOST_PATH:CONTAINER_PATH

Q5. GitLab me multiple mounts kyu use karte hain?

GitLab ke application data, logs aur configuration ko separately persist/manage karne ke liye.

Q6. Bind mount aur named volume me difference?

Bind mount me host ka explicit path diya jata hai, jabki named volume ko Docker manage karta hai.

Q7. :ro ka meaning?

Read-only mount.

Q8. Container delete hone par bind-mounted host data ka kya hota hai?

Normal container removal se host directory automatically delete nahi hoti.

Q9. Compose volume configuration kaise check karenge?

docker compose config

Q10. GitLab ko browser se kaise access karenge?

http://localhost:8000
