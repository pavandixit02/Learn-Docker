GitLab Server with Docker Compose

Learn how to run a complete GitLab CE Server using Docker Compose and understand every important Compose keyword used in the configuration.

1. What Are We Going to Learn?

Is lesson me hum GitLab Community Edition (GitLab CE) ko manually docker run command se run karne ke instead Docker Compose ka use karke run karenge.

Docker Compose ka main benefit ye hai ki container ki complete configuration ek YAML file me define ho jati hai.

compose.yml
↓
Docker Compose
↓
GitLab Container
↓
GitLab Server
↓
Browser → http://localhost:8000

2. Why Use Docker Compose?

Agar hum Docker CLI se GitLab run karein to ek long command likhni pad sakti hai: 

docker run -d \
--name my-gitlab-server \
-p 8000:80 \
gitlab/gitlab-ce

Problem ye hai ki configuration yaad rakhni padti hai. Docker Compose me hum ye configuration ek file me save kar dete hain. 

docker compose up -d
Simple idea: Compose file = Container ki configuration ka blueprint.

3. Step 1 — Project Directory Create Karein

mkdir gitlab-compose
cd gitlab-compose

Ab isi directory ke andar hum Compose file create karenge. 

nano compose.yml

Ya VS Code se directly compose.yml file create kar sakte hain.

4. Step 2 — GitLab Compose File

Basic learning configuration: 

services:

  gitlab-server:

    image: 'gitlab/gitlab-ce'

    container_name: my-gitlab-server

    ports:
      - '8000:80'

    environment:
      GITLAB_OMNIBUS_CONFIG: |
        gitlab_rails['initial_root_password'] = 'YOUR_PASSWORD'
        puma['worker_processes'] = 0
Security: Real project me password ko directly Compose file me hard-code nahi karna chahiye. Environment file, Docker secrets, ya another secure secret-management approach use karein.

5. Important: version: '5.5.1' ka Kya Meaning Hai?

Bahut beginners ko ye confusion hota hai ki: 

version: '5.5.1'

kya ye GitLab ka version hai?

Answer: Nahi.

Ye GitLab application version nahi hai. Ye historically Docker Compose file format/schema version ko indicate karta tha.

Modern Docker Compose: Current Compose implementations me top-level version field obsolete/ignored ho sakti hai. Isliye naye projects me normally is field ko omit karna better hai.

Agar aapko GitLab ka specific version run karna hai, image tag specify karein: 

image: 'gitlab/gitlab-ce:18.4.1-ce.0'

Yahan 18.4.1-ce.0 GitLab image ka version/tag hai.

6. services Keyword

services:

services Docker Compose ka main section hai. Iske andar hum batate hain ki application ke kaun-kaun se containers/services run honge.

Example: 

services:

  gitlab-server:

Yahan gitlab-server service ka naam hai.

Remember:
services → containers/applications define karne ke liye use hota hai.

7. gitlab-server Keyword / Service Name

services:

  gitlab-server:

gitlab-server humara custom service name hai.

Ye naam aap apni requirement ke according change kar sakte hain: 

services:

  gitlab:
  
  # or
  
  gitlab-server:

Compose commands me service name useful hota hai: 

docker compose up gitlab-server
docker compose logs gitlab-server

8. image Keyword

image: 'gitlab/gitlab-ce'

image batata hai ki container kis Docker image se create hoga.

Yahan: 

gitlab/gitlab-ce

official GitLab Community Edition image ka reference hai.

Specific Version

image: 'gitlab/gitlab-ce:18.4.1-ce.0'

Tag specify karne se specific image version use ki ja sakti hai.

9. container_name Keyword

container_name: my-gitlab-server

Ye container ko custom name deta hai.

Agar ye name nahi diya hota to Compose automatically generated name bana sakta hai.

Custom name hone ke baad: 

docker ps

docker logs my-gitlab-server

docker exec -it my-gitlab-server bash
Work: container_name → Docker container ko readable/custom name dena.

10. ports Keyword

ports:
  - '8000:80'

Ye host machine ke port ko container ke port se connect karta hai.

HOST
localhost:8000
↓
Docker Port Mapping
↓
CONTAINER
port 80
↓
GitLab Web Server

Format: 

HOST_PORT:CONTAINER_PORT

Is case me: 

8000:80
  • 8000 → Ubuntu host machine ka port
  • 80 → GitLab container ka HTTP port

Browser me: 

http://localhost:8000

11. environment Keyword

environment:
  GITLAB_OMNIBUS_CONFIG: |

environment ke andar hum container ke environment variables define kar sakte hain.

Example: 

environment:
  APP_ENV: production

Container ke andar ye variable available hoga: 

APP_ENV=production

12. GITLAB_OMNIBUS_CONFIG

GITLAB_OMNIBUS_CONFIG: |

Ye GitLab Omnibus image ko configuration instructions pass karne ke liye use hota hai.

GitLab Omnibus ke andar GitLab ki services aur configuration ko configure kiya ja sakta hai.

Example: 

GITLAB_OMNIBUS_CONFIG: |
  gitlab_rails['initial_root_password'] = 'YOUR_PASSWORD'
  puma['worker_processes'] = 0

13. YAML me | ka Kya Meaning Hai?

GITLAB_OMNIBUS_CONFIG: |

YAML me | ko literal block scalar kaha jata hai.

Iska matlab hai ki next multiple lines ko ek multiline value ke form me pass karo.

Without |:

KEY: one line value

With |:

KEY: |
  line one
  line two
  line three

GitLab configuration ke case me ye multiple Omnibus configuration lines ko ek environment variable value ke form me pass karta hai.

14. gitlab_rails['initial_root_password']

gitlab_rails['initial_root_password'] = 'YOUR_PASSWORD'

Ye GitLab ke initial root/admin account ka password configure karne ke liye use kiya ja sakta hai.

Login ke time: 

Username:
root

Password:
YOUR_PASSWORD
Important Security Rule: Password ko GitHub/GitLab repository me plain text ke form me commit mat karein. Learning ke liye bhi real password ki jagah placeholder use karna better hai.

15. puma['worker_processes']

puma['worker_processes'] = 0

GitLab ka web application server Puma hai. worker_processes Puma ke worker processes ko configure karta hai.

Learning/lab environment me: 

puma['worker_processes'] = 0

ka use resource consumption ko reduce karne ke liye kiya ja sakta hai, especially jab aap limited RAM wali local machine par GitLab test kar rahe ho.

Production environment ke liye worker/process configuration blindly copy nahi karni chahiye. Server resources aur GitLab recommendations ke according tune karna chahiye.

16. Complete compose.yml

services:

  gitlab-server:

    image: 'gitlab/gitlab-ce'

    container_name: my-gitlab-server

    ports:
      - '8000:80'

    environment:
      GITLAB_OMNIBUS_CONFIG: |
        gitlab_rails['initial_root_password'] = 'YOUR_PASSWORD'
        puma['worker_processes'] = 0

Ye basic learning/lab configuration hai.

17. Step 3 — Compose File Validate Karein

Container start karne se pehle configuration validate karna useful hai: 

docker compose config

Agar YAML/configuration valid hai to Compose rendered configuration show karega. Agar indentation ya syntax error hai to error milega.

18. Step 4 — GitLab Image Pull Karein

docker compose pull

Ye Compose file me specified image ko registry se pull karega.

Is case me: 

gitlab/gitlab-ce

19. Step 5 — GitLab Container Start Karein

docker compose up -d

Yahan:

  • up → services create/start karta hai
  • -d → detached/background mode

Agar image locally available nahi hai to Compose automatically image pull kar sakta hai.

20. Step 6 — Container Check Karein

docker compose ps

Ya: 

docker ps

Aapko my-gitlab-server container running state me dikhna chahiye.

21. Step 7 — GitLab Logs Check Karein

docker compose logs -f gitlab-server

-f ka meaning hai logs ko continuously follow karna.

GitLab heavy application hai, isliye first startup me time lag sakta hai.

Exit karne ke liye: 

Ctrl + C
Container ko stop karne ke liye Ctrl+C use karna zaroori nahi hai jab Compose detached mode me run hua ho. Logs follow karte waqt Ctrl+C sirf log viewing ko stop karta hai.

22. Step 8 — Browser Se GitLab Open Karein

Browser me open karein: 

http://localhost:8000

GitLab login page open hona chahiye.

Initial root credentials aapke Compose configuration ke according honge.

23. Step 9 — GitLab Login

Username:
root

Password:
YOUR_PASSWORD

Login successful hone ke baad aap GitLab dashboard access kar sakte hain.

24. Container ke Andar Command Run Karna

Container ke andar shell open karne ke liye: 

docker exec -it my-gitlab-server bash

Isse aap GitLab container ke andar enter kar sakte hain.

Exit: 

exit

25. GitLab Stop Karna

docker compose stop

Ye container ko stop karta hai, lekin Compose resources ko remove nahi karta.

26. GitLab Dobara Start Karna

docker compose start

Pehle se created/stopped services ko dobara start karta hai.

27. GitLab Remove Karna

docker compose down

Ye Compose-created containers aur networks ko remove karta hai.

Important: GitLab jaisi stateful application ke liye persistent volumes use karna important hai. Simple lab configuration me data persistence properly configure na ho to container removal ke baad important data lose ho sakta hai.

28. Compose File Keywords — Quick Reference

Keyword Purpose
services Application/container services define karta hai.
gitlab-server Custom service name.
image Container kis Docker image se create hoga.
container_name Container ko custom name deta hai.
ports Host aur container ke ports map karta hai.
environment Environment variables/configuration provide karta hai.
GITLAB_OMNIBUS_CONFIG GitLab Omnibus configuration instructions pass karta hai.
| YAML multiline value define karta hai.
gitlab_rails['initial_root_password'] Initial GitLab root password configure karta hai.
puma['worker_processes'] Puma web-server worker processes configure karta hai.
version Historical Compose file format field; modern Compose me generally omit kiya jata hai.

31. Common Mistakes

1. YAML indentation error

services:
gitlab-server:

Ye incorrect indentation ho sakti hai.

Correct:

services:
  gitlab-server:

2. Wrong port

ports:
  - '8000:80'

Browser me localhost:8000 open karna hoga.

3. GitLab startup ko immediately ready samajhna

GitLab first startup me considerable time le sakta hai. Logs check karein. 

docker compose logs -f gitlab-server

4. Password GitHub par push karna

Real password ko Compose file me hard-code karke public/private repository me commit karna security risk hai.

5. Data persistence ignore karna

Production-like GitLab setup me configuration, logs aur application data ke liye persistent storage configure karna chahiye.

32. Docker + GitLab Interview Questions

Q1. Docker Compose kya hai?

Docker Compose ek tool hai jo YAML file ke through multi-container applications/services ko define aur manage karta hai.

Q2. services keyword ka kya use hai?

Compose file me application ke services/containers define karne ke liye.

Q3. image aur container me difference?

Image ek read-only template/package hota hai, jabki container us image ka running instance hota hai.

Q4. ports: 8000:80 ka meaning?

Host port 8000 ko container port 80 ke saath map karta hai.

Q5. GITLAB_OMNIBUS_CONFIG kya hai?

GitLab Omnibus Docker image ko GitLab configuration instructions pass karne ke liye environment variable.

Q6. YAML me | ka use?

Multiple lines ko ek multiline string/value ke roop me define karne ke liye.

Q7. docker compose up -d ka meaning?

Services ko create/start karke detached/background mode me run karna.

Q8. docker compose down aur stop me difference?

stop services ko stop karta hai, jabki down Compose-managed containers aur networks ko remove karta hai.

Q9. GitLab container me bash kaise open karenge?

docker exec -it my-gitlab-server bash

Q10. GitLab ko browser se kaise access karenge?

http://localhost:8000

33. Final Summary

Is lesson me humne GitLab Community Edition ko Docker Compose ke through run karna seekha.

Sabse important concepts:

  • services → services define karta hai
  • image → GitLab image select karta hai
  • container_name → custom container name
  • ports → host/container port mapping
  • environment → environment configuration
  • GITLAB_OMNIBUS_CONFIG → GitLab configuration
  • gitlab_rails['initial_root_password'] → initial root password
  • puma['worker_processes'] → Puma worker configuration
  • | → multiline YAML value
  • docker compose up -d → GitLab start
  • docker compose ps → status check
  • docker compose logs -f → logs check
  • docker compose down → Compose resources remove
DevOps Concept: Docker Compose ka main advantage ye hai ki infrastructure/container configuration ko code ke form me define karke repeatable aur manageable banaya ja sakta hai.
